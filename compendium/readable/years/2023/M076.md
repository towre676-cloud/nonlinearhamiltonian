## Revised question retained in the annual source

How do local movement commands map into world coordinates, and when does diagonal input change speed?

## Status

Classical result developed and worked

## Summary

Movement commands can be formulated without ambiguous appeals to trigonometry. Linear algebra combines the local commands; a rotation converts the resulting vector into another frame. Keeping magnitude conventions explicit resolves diagonal-speed discrepancies.

## Definitions

In a right-handed plane use column vectors and counterclockwise rotation R(θ)=[[cosθ,−sinθ],[sinθ,cosθ]]. Let a local command u=(u₁,u₂) specify components in orthonormal local axes. World velocity is v=su rotated by R, namely v=sR(θ)u.

## Result name

Rotation preserves speed but raw diagonal input changes it

## Result statement

Because RᵀR=I, ||v||₂=s||u||₂. A single unit-axis command has speed s, while raw input u=(1,1) has speed s√2. Normalizing nonzero input by its Euclidean norm produces constant speed s regardless of its direction.

## Proof

Multiply the displayed matrix by its transpose and use cos²θ+sin²θ=1 and cancellation of the cross terms. Taking squared norms then gives the identity. The difference between axis and diagonal commands follows from ||(1,0)||=1 and ||(1,1)||=√2. If the desired control preserves analog intensity below unit radius, the mapping u↦u/max(1,||u||) leaves small commands unchanged and caps only those outside the unit disk. This is a specified control law, not a consequence forced by coordinate geometry.

## Worked example: setup

Use the exact rotation with cosθ=3/5 and sinθ=4/5.

## Worked example: calculation

The unit forward command maps to (3/5,4/5), of squared norm one. The unnormalized diagonal maps to (−1/5,7/5), of squared norm two. Its normalized version divides both components by √2, returning squared norm one. These checks use exact rational arithmetic before the final normalization.

## Worked example: conclusion

Coordinate conversion and speed policy can be independently tested. This makes it possible to change a frame without silently changing the physical or numerical interpretation of commands.

## Limits

Nonorthogonal coordinate bases, perspective projection, acceleration limits and a non-Euclidean metric alter the formula or the appropriate norm. Time-dependent frames introduce additional derivative terms when differentiating positions.

## Extension

Specify an anisotropic metric or acceleration constraint, then derive the admissible velocity set and a frame-consistent control projection onto it.
