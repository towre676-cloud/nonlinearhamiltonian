## Revised question retained in the annual source

What exact computational problem is proposed, what is public, and what evidence or reduction supports its difficulty?

## Status

A toy encryption proposal is explicitly broken

## Summary

Sophisticated number systems do not themselves supply one-wayness. A mathematically assessable proposal must say what an adversary receives, what recovery problem is being claimed difficult, and how problem instances are distributed.

## Definitions

A toy modular scheme publishes a prime p and nonzero multiplier a and maps a message x to y=ax modulo p.

Correctness of a private recovery algorithm is different from hardness of public recovery.

An instance distribution specifies which public parameters, secrets and observations occur; worst-case difficulty alone need not control that distribution.

## Result name

Public linear arithmetic is publicly invertible

## Result statement

For the stated toy map, every message is recovered from public data using x=a^(−1)y modulo p. Extended Euclid computes a^(−1), so adding large notation or expressing the same arithmetic p-adically cannot turn this construction into a secret inversion problem.

## Proof

Since p is prime and a is nonzero modulo p, gcd(a,p)=1. The extended Euclidean algorithm produces integers u,v with ua+vp=1. Reducing modulo p gives ua≡1, and multiplying y=ax by u recovers x≡uy. This is a deterministic polynomial-time attack in the bit length of p. More generally, a public invertible linear transformation over a field is inverted by linear algebra. If its matrix is hidden but an oracle permits arbitrary message queries, querying the coordinate basis recovers its columns. Neither attack needs to search the message space or exploit implementation defects. They attack the mathematical specification itself.

## Worked example: setup

Take p=101, a=7 and observed y=35.

## Worked example: calculation

Euclid gives 7^(−1)≡29 modulo 101, since 7·29=203≡1. Therefore x≡29·35≡5. The verifier recovers x using only these public quantities. A larger prime changes the input size but not the kind of attack.

## Worked example: conclusion

The construction is correct as a reversible encoding and fails as a claimed secret arithmetic trapdoor.

## Limits

This example does not establish security or insecurity of an unrelated fully specified cryptosystem. A different map might pose a genuinely different problem, but its hardness must be argued independently of the prestige of its geometric or arithmetic vocabulary.

## Extension

For any proposed replacement, give generation, evaluation, recovery, correctness and an explicit public attack model. Test algebraic simplifications on small instances before attaching a security claim.
