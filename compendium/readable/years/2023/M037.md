## Revised question retained in the annual source

Which generator polynomial defines the intended code, what is its minimum distance, and how many errors does nearest-codeword decoding guarantee to correct?

## Status

Specified code completely enumerated

## Summary

The parameters are not merely a label: a generator polynomial, field convention and finite enumeration identify the exact code and establish the correction guarantee.

## Definitions

Work over F₂ and take α as a root of x⁴+x+1 in F₁₆. The verifier checks that α has multiplicative order fifteen.

Let g(x)=(x⁴+x+1)(x⁴+x³+x²+x+1)=x⁸+x⁷+x⁶+x⁴+1.

The cyclic code C consists of m(x)g(x) for deg m<7, represented as length-fifteen binary words. Hamming weight counts nonzero coordinates.

## Result name

This standard narrow-sense BCH construction has parameters [15,7,5] and corrects any two errors

## Result statement

The generator divides x¹⁵−1 and vanishes at α,α²,α³,α⁴. There are exactly 128 codewords and the least nonzero weight is five. Consequently distinct radius-two Hamming balls are disjoint.

## Proof

The root checks identify the designed-distance-five BCH construction. Polynomial division verifies cyclic divisibility. Multiplication by the nonzero monic g is injective on the 128 degree-below-seven messages, and the resulting degree is below fifteen; this establishes length and dimension. For a linear code, the distance between two codewords is the weight of their difference, another codeword, so minimum distance equals minimum nonzero weight. Exhaustive enumeration establishes that minimum as five. If a received word were within distance two of two codewords, the triangle inequality would put those codewords within distance four, a contradiction. Thus nearest-codeword decoding succeeds for every error pattern of weight at most two.

## Worked example: setup

Enumerate all messages and all error patterns of weights zero, one and two.

## Worked example: calculation

The exact weight enumerator is 1+18z⁵+30z⁶+15z⁷+15z⁸+30z⁹+18z¹⁰+z¹⁵. There are 1+15+C(15,2)=121 allowed error patterns per codeword, and the verifier obtains 128×121=15,488 distinct received words in the union of the decoding balls.

## Worked example: conclusion

The earlier one-error description understated the guarantee of this specified construction. The result is exhaustive for this finite code, including a reproducible generator and decoder-radius certificate.

## Limits

The code is not perfect: the 15,488 radius-two words do not exhaust all 32,768 binary words. The certificate says nothing about guaranteed correction of every three-error pattern. Other codes with the same length and dimension need not share the minimum distance.

## Extension

Publish syndrome calculation and a bounded-distance decoder, then compare decoder output against exhaustive nearest-codeword results on all received words. Treat larger parameters with algebraic decoding proofs rather than assuming enumeration remains cheap.
