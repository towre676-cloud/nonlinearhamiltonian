## Revised question retained in the annual source

Which algebraic laws make replay deterministic, and why does idempotent recovery not imply idempotent event application?

## Status

Developed mathematical treatment with explicit hypotheses, derivation and checked example

## Summary

A free-monoid action formalizes deterministic event replay without requiring a commutative state update. Selecting a certified log prefix is idempotent, while duplicate events and cross-shard invariants remain separate obligations.

## Definitions

Let Σ* be finite event words with concatenation and empty word. Each event e defines a deterministic transition T_e:S→S.

For a word w=e₁…e_n define T_w=T_{e_n}∘…∘T_{e₁}; thus T_{uv}=T_v∘T_u.

A recovery map R retains the longest prefix whose declared commit metadata is valid and retains that metadata unchanged.

## Result name

Replay and recovery identities

## Result statement

Fold(s,uv)=Fold(Fold(s,u),v). If a retained prefix remains certified under recovery, then R(R(w))=R(w). These identities do not require T_e²=T_e and do not guarantee that independently replayed shards preserve a shared invariant.

## Proof

The fold law follows by induction on the length of v: each appended event applies the same deterministic map to the previous state. For recovery, the first result is already a certified maximal retained prefix of itself, so running the same prefix selection again leaves it unchanged. This is idempotence of a projection on logs, not idempotence of transitions on application state. If an event increments a counter, replaying the same event twice increments twice unless deduplication semantics are explicitly part of T_e. Product replay across shards is valid only for a declared product state and independent transitions; a shared constraint couples those factors.

## Worked example: setup

Use a counter initially zero and events inc(2),inc(3),inc(5), of which only the first two are committed.

## Worked example: calculation

The full fold is ten; recovered replay is five. Recovering that two-event prefix again still yields five. Replaying inc(3) twice would yield eight after inc(2), demonstrating that deterministic replay alone does not deduplicate. If two shards each authorize a withdrawal of 60 against one shared budget of 100 without coordination, their individually valid checks can jointly overspend by 20.

## Worked example: conclusion

The algebra certifies a specified replay map while identifying independent application invariants.

## Limits

A mathematical certified-prefix assumption does not prove a storage device’s persistence, fence or power-failure semantics. Hash streams, writer exclusion and acknowledgments require their own implementation contracts.

## Extension

Specify a crash model and prove a refinement from physical writes to the abstract prefix projection. Add explicit event identities for deduplication and prove preservation of any global invariant under the allowed concurrency relation.
